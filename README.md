# Cognito Study — 認証ハンズオン問題集

用意されたUIのTODOを埋めて、登録 → メールコード確認 → ログイン → TOTP初回設定・MFA → サインアウトを学びます。

認証処理は各ページのハンドラー内に直接書きます。共通の認証関数やエラー分類の実装は不要です。ContextはメールとnextStepを渡すだけに使います。

課題の順番・場所・完了条件は[問題集](docs/exercises.md)にあります。

```bash
npm install
npm run dev
```

`.env.example`を参考に`.env.local`へUser Pool IDとApp Client IDを設定します。C01を実装するまでAWSへ接続しません。Cognitoはメールでのログイン・コードによる登録確認・TOTPのみの必須MFA・シークレットなしのApp Clientで設定します。

```tsx
// [COGNITO Cxx START]
// TODO: ここにSDKの呼び出しと結果に応じた処理を書きます。
// [COGNITO Cxx END]
```

コメント間の仮置きのthrowを自分のコードに置き換えてください。認証処理は空欄のままでも起動・ビルドできます。フォームはTODOメッセージを表示します。`/home`と`/mfa/setup`は直接UIプレビューができます。ホームの学習カードには表示専用の参考コードがあります。

## 課題の進め方

1. [問題集](docs/exercises.md)の順番に、対象ファイルの`[COGNITO Cxx START]`〜`END`を開きます。最初はC01の接続設定から始めます。
2. コメントの擬似コードを読み、「どのSDKを呼ぶか」「何を渡すか」「結果を受け取って何をするか」を確認します。
3. コメントを残したまま、その下に実際のコードを書きます。必要なSDKのimportや、Pageの先頭での`useRouter()`の準備も行います。仮置きの`throw new Error('TODO ...')`は置き換えます。
4. SDKから返った`isSignedIn`や`nextStep`を使い、同じハンドラー内に条件分岐と画面遷移を書きます。コードが少し重複しても、まずはそのページだけで流れを読めることを優先します。
5. 1つの課題を書いたらブラウザで動かし、問題集の完了条件を確認して次へ進みます。迷ったらホームの学習カードで参考コードと返り値の例を確認できます。

基本課題は次の2つの流れで確認します。

- 初回：新規登録 → メールコード確認 → ログイン → 認証アプリの初回設定 → ホーム
- 2回目以降：サインアウト → ログイン → 認証アプリのコード確認 → ホーム

登録確認はログインとは別の処理です。基本課題では自動サインインを使わず、メール確認後にログイン画面へ進みます。`nextStep`をページ間で渡すときだけContextを使い、認証処理は各ページに直接書いてください。

最後に、コードを間違えた場合のエラー表示と、登録確認コードの再送も試します。エラーはまずSDKのメッセージをそのまま確認し、エラー名ごとの分類や共通化は後回しで構いません。

## 実装後の確認

```bash
npm run lint
npx next build --webpack
```

実際の認証は[確認順序](docs/exercises.md#前提と確認順序)に沿って確認します。共通関数用のtest:authは廃止しました。

自動サインイン、MFA方式の選択、Lambda経由の実装は発展課題です。`[LAMBDA Lxx START]`〜`END`のコメントはそのまま使えます。
